\begin{abstract}
We tackle the quantum circuit routing problem with two deep reinforcement learning agents sharing the same gymnasium environment with a 5-channel spatial state. Quantum hardware only executes two-qubit gates between adjacent qubits, so the compiler inserts SWAPs; the goal is to minimise SWAP overhead against IBM's SABRE baseline. We implement an off-policy d3qn+per agent (\texttt{ali-dev} branch) and an on-policy ppo agent with a symmetric score map (\texttt{elora-ruche} branch). D3qn beats SABRE on \texttt{heavy\_hex\_19} (ratio 0.969). Ppo beats SABRE by 12.9\% on \texttt{linear\_5} (ratio 0.871). We discuss why off-policy methods dominate on the hardest topology.

\keywords{Reinforcement learning \and Quantum compilation \and PPO \and D3QN \and Combinatorial optimisation.}
\end{abstract}

\section{Motivation and problem}

Quantum computers can only execute two-qubit gates between physically adjacent qubits. Real circuits contain gates between arbitrary qubit pairs, so the compiler must insert SWAP gates to bring qubits next to each other. Each SWAP costs 3 CNOTs and adds decoherence, so the goal is to minimise the number of inserted SWAPs. This is the qubit routing problem, np-hard in general~\cite{siraichi2018}. The industry baseline is SABRE~\cite{li2019sabre}, a bidirectional greedy heuristic in ibm qiskit; it is fast but can miss globally optimal routes.

We chose this problem because it is a real nisq bottleneck, has a natural mdp structure (state = partial routing, action = swap), and is a hard combinatorial problem where rl can plausibly beat hand-crafted heuristics. We implemented two agents to compare on-policy and off-policy methods on the same environment.

\section{Environment}

\paragraph{State space.} The state is a $5 \times 27 \times 27$ float tensor, padded to 27 to fit all topologies in the same network. The five channels encode: (0) hardware adjacency (binary, constant per episode), (1) qubit mapping as a permutation matrix, (2) depth-decayed gate demand $\gamma^{\text{depth}}$ with $\gamma=0.5$, (3) front-layer distance map ($1/d$ for each ready gate's two qubits), (4) stagnation signal (uniform $\text{steps\_since\_last\_gate} / \text{max\_steps}$). Channels 0--2 are the original 3-channel state. Channels 3--4 were added because the 3-channel version caused q-value collapse.

\paragraph{Action space.} \texttt{Discrete(max\_edges)}. Each action selects one hardware edge for a swap. Two qubits cannot be swapped if they do not share a hardware edge. Invalid edges (beyond the current topology) get $-\infty$ logits/q-values before softmax/argmax.

\paragraph{Reward.} Per step: $r = \text{gates\_executed} - 0.05 + 0.1 \cdot \Delta\text{distance} + \text{penalties} + \text{terminal}$. Completion bonus is $+15$ (ppo) or $+5$ (d3qn); timeout penalty $-8$ (ppo) or $-10$ (d3qn). Penalties handle edge repetition (reverse swap $-0.2$, progressive same-edge $-0.2 \times \text{streak}$ capped at $-2$) and stagnation ($-0.03 \times \text{streak}$ capped at $-1.5$). Without them the agent oscillates between two swaps for a small distance shaping reward.

\paragraph{Episode flow.} On reset we pick a topology, generate a random circuit, and set an initial mapping (80\% random, 20\% sabre). On each step, the agent picks an edge, the swap is applied, then all front-layer gates whose two qubits are now adjacent execute automatically (with cascading). The episode ends when all gates are routed, after \texttt{max\_steps}, or after a no-progress streak. Max steps is dynamic: $10 \times \text{num\_gates}$, clamped to $[60, 450]$.

\section{Agents}

Both agents share the same cnn backbone: \texttt{Conv2d(5,32) -> Conv2d(32,64) -> Conv2d(64,32)}, all $3 \times 3$ with relu, flattened to 23{,}328 features.

\paragraph{D3QN + PER (off-policy).} The d3qn agent uses double dueling deep q-learning with prioritized experience replay~\cite{wang2016dueling,vanhasselt2016double,schaul2016per}. After the backbone, two heads produce $V(s)$ and $A(s, a)$, combined as $Q(s,a) = V(s) + A(s,a) - \text{mean}(A)$. Action selection is $\epsilon$-greedy ($\epsilon: 1.0 \to 0.02$). Training stores transitions in a sumtree-based per buffer (capacity 300--500k). Every 4 env steps we sample a minibatch of 128 weighted by td error, compute the double dqn target, and minimise huber loss with importance-sampling correction. Soft target updates use $\tau = 0.005$ every 500 steps. The replay buffer reuses each transition $\sim$50 times; per focuses on rare hard cases (gates near the end of a circuit, awkward mappings) where the value function needs the most updates.

\paragraph{PPO with symmetric score map (on-policy).} The ppo agent~\cite{schulman2017ppo} uses the same backbone with an actor-critic head. The policy head is a $1 \times 1$ convolution producing a $27 \times 27$ score map, symmetrised as $S = (S + S^T) / 2$. This bakes in $\text{swap}(i, j) = \text{swap}(j, i)$ at the architecture level. Edge logits are gathered at hardware edge positions, masked to $-\infty$ on invalid edges, then softmaxed. The value head is a small mlp giving $V(s)$. Training collects rollouts of 4096 steps, computes gae advantages ($\lambda = 0.97$), then runs 8 epochs of clipped ppo updates on minibatches of 256. Hyperparameters: lr $3 \times 10^{-4}$ (annealed to $3 \times 10^{-5}$), $\gamma = 0.995$, clip range 0.15, entropy coef $0.003 \to 0.0001$.

Vanilla ppo collapses on this combinatorial action space: the policy spams one swap. We added (i) a reverse-swap penalty, (ii) a progressive same-edge penalty, (iii) early termination on no-progress streaks, (iv) an action-repeat logit penalty subtracted from the previous action's logit at forward pass, and (v) the symmetric score map. Without these, ppo on \texttt{linear\_5} had a 75\% timeout rate; with them it converged to 0\% timeout in under 2m steps.

\noindent Table~\ref{tab:results} summarises the headline numbers. Ppo beats SABRE by 12.9\% on \texttt{linear\_5} (14.1 vs 16.2 swaps), converging in under 250k steps. On \texttt{grid\_3x3}, lr annealing eliminated late-training regression and ppo plateaus at ratio 1.096 with 100\% completion. Heavy\_hex\_19 was attempted with three configurations (single-stage 8m, curriculum $5\to 10\to 16$, curriculum $5\to 10\to 20$); none converged within 24h. The policy entropy stayed near uniform on the 22-action space. D3qn solved heavy\_hex with brute force: run 019 (80k episodes, $\approx$ 24m env steps) reaches ratio 0.991. The fine-tuning run reloads its best checkpoint and continues with $\text{lr} = 10^{-5}$ and $\epsilon = 0.05 \to 0.01$, reaching \textbf{ratio 0.969} in 20k more episodes. A single multi-topology d3qn agent (run 018) matches SABRE overall (0.999) and beats it on \texttt{linear\_5}.

Figure~\ref{fig:training} shows the characteristic d3qn learning curve: a long warm-up (negative reward, no completion), then a sharp phase transition around episodes 8k--12k where the q-function starts to discriminate good swaps and the swap count crosses the SABRE baseline. The remaining 65k episodes refine the policy from $\sim$200 swaps per circuit to the final 183.

\paragraph{Discussion.} Ppo wins on the smallest topology where the 4-action space is easy to explore on-policy; d3qn dominates on larger topologies thanks to its sample-efficient replay buffer. On-policy methods need abundant fresh data, off-policy methods win when sample efficiency matters and the action space is large. The 5-channel state was the single biggest contribution: both agents collapsed without channels 3--4. The front-layer distance map gives a direct gradient towards executable gates and the stagnation channel lets the value function detect dead-end loops. Distance shaping~\cite{pozzi2022} removed $\sim$15k episodes of d3qn warm-up; lr annealing and curriculum learning gave a 25\% training-time saving. Fine-tuning a converged checkpoint at lr $10^{-5}$ improved ratio from 0.991 to 0.969 in only 20k episodes --- the highest-impact technique we found. Figure~\ref{fig:per_category} breaks down the win/loss rate per circuit category: the agent dominates on linear-algebra workloads but loses on the simplest synthetic circuits, where our routing margins are smallest.

The fundamental limit of our ppo runs on heavy\_hex is wall-clock: $\sim$430k env steps/hour cannot match d3qn's 24m steps in a 24h slot. Failed attempts: action history channel (regression on grid), n-step returns for d3qn ($Q$ collapsed to $-123$), doubling gate reward (ratio 1.014 $\to$ 1.377). Future work: vectorised envs for ppo, transfer learning from grid to heavy\_hex, hybrid rl+mcts at inference.
