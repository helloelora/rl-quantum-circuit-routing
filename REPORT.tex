\section{Motivation}

Quantum computers can only execute two-qubit gates between physically adjacent qubits. Real circuits contain gates between arbitrary qubit pairs. The compiler must therefore insert SWAP gates to bring qubits next to each other before each two-qubit gate can run. Each SWAP costs 3 CNOTs. More CNOTs means more decoherence and lower fidelity, so the goal is to minimise the number of inserted SWAPs.

This is the \textbf{qubit routing problem}. It is np-hard in the general case (siraichi et al., 2018). The industry baseline is \textbf{SABRE} (li et al., 2019), a bidirectional greedy heuristic shipped with ibm qiskit. SABRE is fast but greedy, so it can miss globally optimal routes.

We chose this problem for three reasons. First, it is a real bottleneck in current nisq hardware. Second, it has a natural mdp structure: each state is a partial routing, each action is a swap. Third, it is a hard combinatorial problem where rl can plausibly beat hand-crafted heuristics, which is one of the few clean wins for rl over classical algorithms.

We implemented two agents to compare on-policy and off-policy methods on the same environment. Ali built a \textbf{d3qn + per} (off-policy, value-based) agent on the \texttt{ali-dev} branch. Elora built a \textbf{ppo} (on-policy, actor-critic) agent on the \texttt{elora-ruche} branch. Both share the same gymnasium environment.

\section{Environment}

The environment is a custom gymnasium env: \texttt{QubitRoutingEnv}. It is shared between both agents.

\subsection{State space}

The state is a $5 \times 27 \times 27$ float tensor. The matrix is padded to 27 to support all topologies with the same network. The five channels are:

\begin{table}[h]
\centering
\small
\begin{tabularx}{\textwidth}{c X l}
\toprule
\textbf{Channel} & \textbf{Encodes} & \textbf{Updated} \\
\midrule
0 & hardware adjacency (binary) & constant per episode \\
1 & qubit mapping (permutation matrix, 1 at $[q, p]$ if logical qubit $q$ is at physical position $p$) & every swap \\
2 & depth-decayed gate demand ($\gamma^{\text{depth}}$ accumulated, $\gamma = 0.5$) & when gates execute \\
3 & front-layer distance map ($1/\text{distance}$ for each ready gate's two qubits) & every swap \\
4 & stagnation signal ($\text{steps\_since\_last\_gate} / \text{max\_steps}$, uniform) & every swap \\
\bottomrule
\end{tabularx}
\end{table}

Channels 0--2 are the original 3-channel state. Channels 3--4 were added later because the 3-channel version caused q-value collapse --- the network gave the same value to every state and the policy degenerated. Channel 3 gives a direct signal on which gates are close to executable. Channel 4 tells the agent it is stuck and should change strategy.

\subsection{Action space}

The action space is \texttt{Discrete(max\_edges)}, where \texttt{max\_edges} is the largest edge count across all supported topologies. Each action selects one hardware edge on which to perform a swap. Actions beyond the current topology's edge count are masked: their logits / q-values are set to $-\infty$ before the softmax / argmax. Two qubits cannot be swapped if they do not share a hardware edge.

\subsection{Reward}

The per-step reward combines a sparse progress signal with several shaping terms:

\begin{lstlisting}
r = gates_executed * gate_reward            # +1 per gate routed
  + distance_coeff * delta_distance         # pozzi-style distance shaping
  + step_penalty                            # -0.05 per step
  + reverse_swap_penalty                    # -0.2 if same swap as previous
  + repeat_swap_penalty                     # -0.2 * streak (capped at -2.0)
  + no_progress_penalty                     # -0.03 * streak (capped at -1.5)
  + completion_bonus (if all gates routed)  # +15 (ppo) / +5 (d3qn)
  + timeout_penalty (if truncated)          # -8 (ppo) / -10 (d3qn)
\end{lstlisting}

The repetition and stagnation penalties are critical. Without them the agent learns to repeat one swap forever or oscillate between two swaps, since both give a small distance shaping reward.

\subsection{Episode flow}

\begin{enumerate}[leftmargin=*]
\item \textbf{Reset:} pick a topology, generate a random circuit (depth 5--20 depending on the curriculum stage), set an initial mapping (80\% random, 20\% sabre).
\item \textbf{Step:} the agent picks an edge. The swap is applied. All front-layer gates whose two qubits are now adjacent execute automatically (with cascading if a gate execution unlocks the next layer).
\item \textbf{Terminate:} when all gates are routed (success), or after \texttt{max\_steps} (timeout), or after a no-progress streak (early truncation).
\end{enumerate}

The maximum number of steps per episode is dynamic: $\text{max\_steps} = 10 \times \text{num\_two\_qubit\_gates}$, clamped between 60 and 450. Easy circuits get tighter budgets, hard circuits get more room.

\section{Agents}

\subsection{D3QN + PER (Ali, off-policy)}

The d3qn agent is a \textbf{double dueling deep q-network} with \textbf{prioritized experience replay}. Full code, configs, and results live on the \texttt{ali-dev} branch: \url{https://github.com/helloelora/rl-quantum-circuit-routing/tree/ali-dev}.

\paragraph{Network.} The 5-channel state goes through the shared cnn backbone (\texttt{Conv2d(5,32) -> Conv2d(32,64) -> Conv2d(64,32)}, all $3 \times 3$ with relu). Then a flatten feeds two heads:

\begin{itemize}[leftmargin=*]
\item \textbf{Value stream:} \texttt{linear(23328, 256) -> relu -> linear(256, 1)} $\to V(s)$.
\item \textbf{Advantage stream:} \texttt{linear(23328, 256) -> relu -> linear(256, num\_edges)} $\to A(s, a)$.
\end{itemize}

The dueling combination is $Q(s, a) = V(s) + A(s, a) - \text{mean}(A)$. The mean subtraction is what makes the decomposition identifiable (otherwise $V$ and $A$ could shift by an arbitrary constant). The advantage stream learns "which swap is best given the state", and the value stream learns "how good is this state in general". This separation converges much faster than learning q-values directly, especially when many actions have similar values.

\paragraph{Training loop.}

\begin{enumerate}[leftmargin=*]
\item Collect a transition $(s, a, r, s')$ via epsilon-greedy exploration. Epsilon decays from 1.0 to 0.02 over 4--6m steps.
\item Store it in a prioritized replay buffer (sumtree, capacity 300--500k). New transitions get the maximum priority so they are sampled at least once.
\item Every 4 environment steps, sample a minibatch of 128 transitions weighted by td error.
\item Compute the \textbf{double dqn target}: pick the action with the online network, evaluate it with the target network. This eliminates the q-value overestimation bias of vanilla dqn.
\item Minimise huber loss weighted by the per importance-sampling correction (beta annealed from 0.4 to 1.0).
\item Soft-update the target network with polyak averaging ($\tau = 0.005$ every 500 steps).
\end{enumerate}

\paragraph{Why off-policy works here.} The replay buffer reuses each transition $\sim$50 times. Per focuses sampling on transitions with high td error, which tend to be the hard, rare cases (gates near the end of a circuit, awkward mappings). This is exactly where the value function needs the most updates.

\subsection{PPO with symmetric score map (Elora, on-policy)}

The ppo agent is a \textbf{proximal policy optimisation} actor-critic. Code lives on the \texttt{elora-ruche} branch.

\paragraph{Network.} Same shared cnn backbone as d3qn. Then two heads:

\begin{itemize}[leftmargin=*]
\item \textbf{Policy head:} \texttt{Conv2d(32, 1, 1x1)} produces a $27 \times 27$ spatial score map. The map is symmetrised: $S = (S + S^T) / 2$. This bakes in the constraint $\text{swap}(i, j) = \text{swap}(j, i)$ at the architecture level. Edge logits are gathered from the symmetric score at the position of each hardware edge. Invalid edges get $-\infty$. A softmax gives the action distribution.
\item \textbf{Value head:} \texttt{Linear(23328, 256) -> relu -> Linear(256, 1)} $\to V(s)$.
\end{itemize}

\paragraph{Training loop.}

\begin{enumerate}[leftmargin=*]
\item Collect a rollout of 4096 environment steps with the current policy. The policy is frozen during collection.
\item Compute \textbf{gae advantages} ($\lambda = 0.97$) for every step in the rollout, using $V(s)$ as the baseline.
\item For 8 epochs, shuffle the rollout into minibatches of 256, compute the clipped ppo objective, and gradient-step on \texttt{policy\_loss + 0.5 * value\_loss - entropy\_coef * entropy}.
\item Throw the rollout away. Collect a new one with the updated policy. Ppo is on-policy: old data is no longer valid because the policy that generated it has changed.
\end{enumerate}

\paragraph{Anti-collapse engineering.} Vanilla ppo collapses on this combinatorial action space. The policy converges to spamming a single swap, since the entropy bonus is too weak to prevent it on a 22-action space and the action distribution can become very peaked. We added several fixes:

\begin{itemize}[leftmargin=*]
\item \textbf{Reverse-swap penalty} ($-0.2$) for choosing the same edge as the previous step.
\item \textbf{Progressive same-edge penalty} ($-0.2 \times \text{streak}$, capped at $-2.0$).
\item \textbf{No-progress termination}: kill the episode after 30--50 steps without any gate executed.
\item \textbf{Action-repeat logit penalty} ($-0.20$) subtracted from the logit of the previous action during the forward pass. This is a soft anti-loop bias at the policy level.
\item \textbf{Symmetric score map} in the policy head, as described above.
\end{itemize}

Without these, ppo on \texttt{linear\_5} had a 75\% timeout rate. With them, it converged to a stable 0\% timeout in under 2m steps.

\paragraph{Hyperparameters used.}

\begin{itemize}[leftmargin=*]
\item Learning rate: $3 \times 10^{-4}$ (annealed to $3 \times 10^{-5}$ with linear schedule on most runs)
\item $\gamma$: 0.995, gae $\lambda$: 0.97
\item Clip range: 0.15
\item Update epochs: 8, minibatch size: 256
\item Entropy coef: $0.003 \to 0.0001$
\item Distance reward coef: $0.03 \to 0.015$ (annealed to reduce shaping bias late in training)
\end{itemize}

\section{Results}

\subsection{PPO results (elora-ruche branch)}

\begin{table}[h]
\centering
\small
\begin{tabular}{lcccc}
\toprule
\textbf{Topology} & \textbf{Steps} & \textbf{Best ratio} & \textbf{Win rate} & \textbf{Completion} \\
\midrule
\texttt{linear\_5} & 2M & \textbf{0.871} & 94\% & 100\% \\
\texttt{grid\_3x3} (lr annealing) & 10M & 1.096 & 38\% & 100\% \\
\texttt{heavy\_hex\_19} (curriculum) & 5M (killed at 24h) & not converged & --- & --- \\
\bottomrule
\end{tabular}
\end{table}

\textbf{Linear\_5 is solved.} ppo uses 14.1 swaps on average vs sabre's 16.2. That is a 12.9\% improvement, with 94\% win rate and 0\% timeout. The agent converged in under 250k steps and stayed stable for the rest of the training.

\textbf{Grid\_3x3 plateaus.} The first run (5m steps, constant lr) reached $-24\%$ improvement at update 1100 then regressed to $-29\%$ by 5m. The lr annealing run (10m steps, $3 \times 10^{-4} \to 3 \times 10^{-5}$) eliminated the regression: it converged to a stable plateau at $-10\%$ improvement (ratio 1.096) for the last 6m steps. The agent completes 100\% of grid circuits but uses $\sim$3 extra swaps per circuit compared to sabre.

\textbf{Heavy\_hex\_19 is unsolved.} Several attempts:
\begin{itemize}[leftmargin=*]
\item 8m steps single-stage: policy stayed near-uniform (entropy 2.99/3.0), 100\% timeout, no learning.
\item 10m steps curriculum (depth 5 $\to$ 10 $\to$ 16): stage 1 and 2 made some progress (entropy dropped to $\sim$2.0), stage 3 timed out at 24h before convergence.
\item 10m steps curriculum (depth 5 $\to$ 10 $\to$ 20, aligned with ali's config): same pattern. Killed at 24h after $\sim$5m steps.
\end{itemize}

The fundamental issue is \textbf{sample efficiency}. ppo throws away each rollout after 8 epochs, while d3qn reuses transitions $\sim$50 times via the replay buffer. To match ali's 24m environment steps, we would need either a much longer wall-clock budget or vectorised environments to batch the inference.

\subsection{D3QN results (ali-dev branch)}

Best single-topology run on \texttt{heavy\_hex\_19}: \textbf{ratio 0.991} (run 019, 80k episodes $\approx$ 24m env steps). The agent uses 183.3 swaps on average vs sabre's 185.3.

The fine-tuning approach (run 029) reloaded run 019's best checkpoint and continued training with $\text{lr} = 10^{-5}$ and $\epsilon = 0.05 \to 0.01$. It reached \textbf{ratio 0.969} in 20k additional episodes --- the best result of the entire project.

Ppo wins on the smallest topology where the 4-action space is easy to explore on-policy. D3qn dominates on the larger topologies thanks to its sample-efficient replay buffer. This matches the conventional wisdom: on-policy methods are better when you have abundant fresh data and a small action space; off-policy methods are better when sample efficiency matters and the action space is large.

\subsection{Discussion}

\paragraph{What worked.}
\begin{itemize}[leftmargin=*]
\item The 5-channel state was the single biggest contribution. Both agents collapsed without channels 3--4, and both converged with them.
\item Ppo's symmetric score map enforces the swap symmetry at the architecture level instead of relying on the network to learn it.
\item D3qn's per is a major sample efficiency win on hard topologies.
\item Lr annealing prevents late-training regression on grid\_3x3 for ppo.
\item Curriculum learning (depth ramp) gives a 25\% training time saving on d3qn for heavy\_hex.
\item Fine-tuning a converged checkpoint with a much lower lr is the highest-impact technique we found ($0.991 \to 0.969$ for d3qn).
\end{itemize}

\paragraph{What didn't work.}
\begin{itemize}[leftmargin=*]
\item The original 3-channel state caused q-value collapse on both agents.
\item Vanilla ppo without anti-collapse engineering spammed one action.
\item Replacing the stagnation channel with a per-position action history channel hurt grid\_3x3 performance, so we reverted.
\item N-step returns for d3qn caused catastrophic divergence (run 25, q-values dropped to $-123$).
\item Doubling the gate reward to 2.0 degraded d3qn ratio from 1.014 to 1.377 --- the agent optimised for gate throughput instead of routing efficiency.
\end{itemize}

\paragraph{Limitations.}
\begin{itemize}[leftmargin=*]
\item Ppo on heavy\_hex remains an open problem with our current step budget. Vectorised environments would likely close the gap.
\item Both agents struggle with the largest available topology (\texttt{heavy\_hex\_27}, 27 qubits) because the action space grows.
\item Training is sensitive to the reward magnitude. Doubling any single component breaks the policy.
\item The "win rate" metric is misleading when the agent times out --- it can show 75\% wins while never completing a circuit (we hit this several times).
\end{itemize}

\paragraph{Future work.}
\begin{itemize}[leftmargin=*]
\item Vectorised environments for ppo to match d3qn's effective batch size.
\item Transfer learning: warm-start ppo on heavy\_hex from a converged grid\_3x3 model.
\item Larger topologies (\texttt{heavy\_hex\_27}) with the same architecture.
\item Hybrid rl + mcts at inference time for an extra optimisation pass.
\end{itemize}
